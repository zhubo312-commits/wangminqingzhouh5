## 1. 定位、依据与当前结论

本盘对应参考站 `pages/xingming/xingming`、`pages/xingming/detail` 与 `pages/xingming/liugeDetail`，实际包含“三才五格”和“三才六格”两种流派。当前生产脚本、接口位置、脚本 SHA-256、两种流派的脱敏请求与关键结果见 `docs/xingming-golden/`。

三个页面脚本只包含表单、结果展示和对远程 `GET /prod-api/app/getPartialAnalysis` 的调用；康熙字表、简繁映射、拼音、笔画、字五行、五格/六格计算、81 数理、三才配置和评分算法均位于参考站服务端，未出现在脚本或当前仓库中。运行时又不得依赖参考站，因此 Definition of Ready 尚未满足，当前不得实现推测算法、静态假盘或开启导航。

非目标：登录、关注校验、广告、悬浮按钮、付费、旧视觉装饰、字典长篇释义和智能老师。姓名学结果只组织已确认的传统结构，不额外生成吉凶结论或建议。

## 2. 原始输入与真实参与条件

| 字段 | 原始页面行为 | 真实请求行为 | 新版要求 |
|---|---|---|---|
| 姓 | 必填，1–2 个汉字 | 作为接口 `lastname` | 必填；保留 1–2 字边界 |
| 名 | 必填，1–3 个汉字 | 作为接口 `firstname` | 五格 1–3 字；六格 1–2 字 |
| 性别 | 男/女，默认男 | 表单值未传；结果页固定传 `sex=1` | 不得假称参与算法；算法来源确认前暂不进入公开契约 |
| 流派 | 三才五格/三才六格，默认五格 | `type=0/1`，决定结果页与计算口径 | 必填枚举 `wuge` / `liuge` |
| 生日 | 无可见控件 | 结果页固定 `1996-12-12 00:00:00` | 当前证据显示不参与；不添加虚构时间输入 |
| 地区 | 无可见控件 | 未传 | 不添加 |
| 真太阳时 | 无可见控件 | 未传 | 不添加 |

对同一脱敏姓名分别使用不同生日与性别调用接口，`data` 逐字段相同。生产脚本中虽然残留 `date`、`area`、`isSolarTime` 状态，但没有渲染控件，也没有进入页面跳转或接口请求。这些状态不能作为产品功能。

## 3. 原始结果与专业阅读路径

### 3.1 三才五格

阅读顺序：姓名字形核验 → 五格数理 → 姓名得分 → 总格数理解读 → 文化提示。

1. 字形核验：每字简体、繁体、拼音、康熙笔画。
2. 五格：天格、人格、地格、外格、总格及对应五行；原页以姓名方格和连线表示格局关系。
3. 姓名得分：参考站返回分值，页面明确“仅作参考”。
4. 总格数理：数理编号、运势类别、总述与详细说明。

### 3.2 三才六格

阅读顺序：姓名字形核验 → 六格数理 → 三才配置 → 三才基础解读 → 文化提示。

1. 字形核验：每字简体、繁体、拼音、康熙笔画、字五行。
2. 六格：天格、人格、地格、外格、总格、变格；展示数值、五行与吉凶，其中变格仅返回数值与吉凶。
3. 三才配置：三才五行组合与综合标签。
4. 三才基础解读：参考站的 `sancaiLiuResult`；不显示接口同时返回但原页未使用的长篇 `content` 等中间内容。

模块拆分原因：字形信息用于核对字库口径；格局数理是核心盘体；得分或三才配置属于辅助研读，不能混入姓名字表。移动端应使用纵向格局列表或关系图的等价重构，不照搬原页固定宽度连线图。

## 5. 规划契约与错误边界

资料齐备后最小请求应为：

```json
{
  "surname": "姓（1–2 字）",
  "givenName": "名（五格 1–3 字，六格 1–2 字）",
  "school": "wuge | liuge"
}
```

响应应稳定返回姓名逐字信息、格局数组、三才配置、评分与已确认的原始解读字段。后端遇到字表无记录、繁简映射歧义、笔画来源冲突或数理表缺项时必须返回字段级错误，明确指出具体字符；禁止按 Unicode 字形、现代简体笔画或模型常识猜测。

规划接口为 `POST /api/v1/paipan/xingming/chart`、`POST /api/v1/paipan/xingming/context` 与 Java 内部 `POST /internal/v1/xingming/chart`。只有完整本地算法和字表通过黄金用例后才允许加入契约、实现接口和配置 `enabled:true`。

## 6. 状态、移动端与验收门槛

- 规划链路：导航 → 姓名学表单 → 结果；结果返回表单，刷新通过短期 `paipan_ref` 恢复。
- 当前没有可运行盘面，不制作静态表单、结果或预览图，以免形成可误开的空壳。
- 资料齐备后，360/390/430px 必须验证长复姓、三字名、繁体、五格与六格两种结果、长篇数理解读、大字号、缺字错误和刷新恢复。
- 开放前必须补齐：经授权的本地字表与版本、五格/六格完整公式、81 数理表、三才组合与评分规则；并对每种姓/名长度组合建立黄金用例。

## 7. 阻塞解除条件

以下任一来源需由用户或算法负责人明确提供并确认授权口径：

1. 参考站 `getPartialAnalysis` 对应服务端实现、数据库快照和版本；或
2. 可离线发布的完整康熙姓名字表（简体、繁体、拼音、康熙笔画、五行）以及与参考站同口径的五格/六格、81 数理、三才和评分算法；或
3. 明确接受另一套可验证算法与其差异范围，并提供覆盖全部长度组合的黄金结果。

在此之前，P06 状态为“阻塞”，`catalog.ts` 保持 `enabled:false`，不增加路由、接口或 Java 猜测实现。
