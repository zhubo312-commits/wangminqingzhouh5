# 专业排盘统一设计规范

版本：1.2<br>
日期：2026-08-11  
适用范围：专业排盘导航及11种排盘的表单页、结果页、状态页  
视觉基线：当前“生平子时”页面与国学 H5 首页

## 专业角色定义

### 角色名称：国学术数专业主编

所有排盘页面在产品设计、内容组织和视觉验收阶段，都必须由“国学术数专业主编”的视角把关。这个角色同时具备两种能力：

- **国学专业能力**：理解不同术数的起盘条件、核心盘体、校验信息、推演关系和辅助信息，知道用户看盘时先看什么、后看什么，以及哪些信息属于同一判断链路。
- **移动端信息设计能力**：能够在360–430px屏幕内，通过模块组合、层级、分隔、留白、段落、渐进展开和触控反馈，把专业信息整理成可连续阅读的页面。

这个角色是页面背后的专业编辑与信息架构师，不等于在所有结果页增加“老师解读”。当前只有子平八字需要智能老师入口；其他盘种仍需按国学专业逻辑组织盘面，但不提供老师解读或自动生成结论。

### 核心职责

每一种排盘在进入视觉设计前，必须先完成以下判断：

1. **盘点原始功能**：逐页、逐状态记录参考站现有的起盘方式、输入选项、默认值、条件显隐、结果模块、辅助工具和页面间跳转，不能只看一张结果截图。
2. **确定专业阅读路径**：说明这张盘从起盘依据、核心盘面到辅助研读的正常阅读顺序，不能直接沿用接口字段顺序。
3. **解释每组信息的用途**：明确它是用于确认排盘条件、阅读核心盘体、判断关系、辅助决策，还是仅为算法中间数据。
4. **重新组织模块**：把属于同一专业问题、同一计算链路、需要来回对照的信息合并；把阅读目的、交互方式或信息密度明显不同的内容拆开。
5. **决定展示层级**：区分始终可见、默认展开、按需展开和不直接展示四个层级，不以“接口有字段”为展示理由。
6. **转译但不篡改**：保留行业通用术语，用副标题、分组名或简短白话说明它的用途；不得为了易懂而改坏术数含义。
7. **控制阅读节奏**：避免连续大表格、连续同形卡片和没有停顿的字段堆叠，让标题、段落、留白和分隔承担清晰的阅读导航。

### 工作边界

- 不凭空补充算法没有返回的吉凶结论、预测或建议。
- 不把原始字段完整罗列等同于“专业、全面”。完整性应由数据契约和测试保证，页面只呈现对当前阅读任务有用的内容。
- 不因追求古风装饰而牺牲字号、对比度、触控面积和阅读顺序。
- 不用大量弹窗打断看盘；优先使用原位展开、折叠和行内详情保持上下文。
- 不把所有专业信息都默认收起，也不把所有信息都默认展开；展开策略必须有专业理由。
- 不得因新版页面暂时没有合适组件、接口字段尚未整理或移动端空间有限，就静默删除原始页面已有的排盘功能。
- 原始页面只作为功能、算法口径和结果完整性的依据，不要求复刻其广告、关注、登录、付费、旧老师入口、旧视觉装饰或工程字段。

### 模块合并与拆分判断

满足以下条件时优先合并：

- 信息共同回答一个专业问题，拆开后需要频繁上下对照。
- 信息属于同一起盘或校验链路，主次关系清楚。
- 合并后能形成“标题 → 核心值 → 依据或补充”的自然段落。

满足以下条件时应当拆分：

- 信息服务于不同阅读目的，例如“确认起盘”与“研读宫位”。
- 其中一组需要点击、筛选或联动，另一组只需阅读。
- 合并后首屏过长、标题失去概括能力，或一个模块内部出现超过三个视觉层级。
- 一组是高频核心信息，另一组只在进阶研读时使用。

以遁甲学为例，“阴遁五局、节气、旬首、值符和值使”共同说明如何起局和核验盘面，应作为一个连续的起局信息模块；九宫盘承担核心研读，应独立成大模块；天三门与地四户属于特定场景的出行辅助，应独立且默认收起。这个判断来自专业关系，而不是卡片数量或字段多少。

## 1. 文档目的

后续10种排盘的业务结构、输入项目和盘面形式可以不同，但必须让用户感到它们属于同一个产品。统一的不是每张盘的数据结构，而是：

- 页面骨架与返回逻辑。
- 宣纸、朱砂、金色和深墨色的视觉语言。
- 字号、行高、间距、边框、圆角和阴影。
- 表单输入、移动端滚轮、结果卡片和选择反馈。
- 文案口径、状态反馈和移动端验收标准。

本规范以当前代码为视觉与工程基线，以经确认的原始页面为单盘功能完整性基线。旧截图中的广告、关注、登录、付费、顶部说明、老师横幅、排盘记录、底部常驻问老师入口等非核心能力，不作为新页面标准；起盘方式、算法参数、结果结构和盘面辅助工具不得据此一并删除。

## 2. 核心设计原则

### 2.1 先照顾阅读，再追求信息密度

主要用户年龄偏大，默认正文不得为了塞入更多内容而缩小。优先换行、分组和平铺，其次才考虑局部滚动。

### 2.2 一屏只建立一个主要阅读层级

页面顺序统一为：

1. 页面头部。
2. 必要的智能解读入口。
3. 用户或问题摘要。
4. 核心盘面。
5. 分组结果与交互模块。
6. 底部智能解读入口与文化提示。

### 2.3 模块节奏统一，内容高度允许自然变化

不同模块可以因内容多少而高低不同，但外部间距、内部留白、标题与内容的距离必须一致。禁止为了“看起来齐”而截断重要内容，也禁止每个页面自行发明一套间距。

### 2.4 尽量不横向滑动

- 页面整体绝不允许横向溢出。
- 大运、流年、流月、候选结果等优先平铺换行。
- 表格优先使用固定列宽、文字分行、纵向列表或卡片化。
- 只有确实无法压缩的专业盘面才允许“表格自身局部横滑”，且不得带动整个页面。

### 2.5 专业术语保留，说明使用白话

盘面字段保留行业标准名称；标题、按钮、错误提示和辅助说明必须使用普通用户能直接理解的中文。不得展示 `sect=2`、接口字段名、算法错误码等工程术语。

### 2.6 先建立专业阅读路径，再决定组件

每张结果页必须先写出一条可读的专业路径，再决定使用卡片、表格、标签或折叠区。推荐基础路径为：

`排盘对象与条件 → 起盘/定盘依据 → 核心盘体 → 关键关系与标记 → 场景辅助 → 参考边界`

不同盘种可以调整顺序，但必须在对应功能设计文档中说明原因。不得因为现成组件方便，反过来拆散本应连续阅读的专业信息。

### 2.7 先保证原始功能完整，再优化表达

每个新盘必须以当前确认的原始页面为功能盘点起点。设计优化可以改变模块顺序、视觉样式和交互承载方式，但不能改变或漏掉算法相关能力。

开发前必须形成“原始功能对照矩阵”，至少覆盖：

- 页面与子页面：入口、表单、结果、详情、说明及必要的返回链路。
- 起盘方式：时间、报数、指定、手工、自动或该盘种实际提供的其他模式。
- 表单语义：全部字段、默认值、选项、范围、互斥关系、条件显隐、历法/地区/方位规则和提交前校验。
- 结果内容：基础核验、核心盘体、标记、关系、时序、辅助信息、说明文字及按需详情。
- 结果工具：上一/下一时段、切换盘式、展开/收起、宫位联动、放大查看、重新排盘及原始页面实际存在的其他工具。
- 状态与异常：加载、无结果、字段错误、服务错误、刷新、返回和重新计算后的数据保留方式。

矩阵中的每一项只能标记为以下四种状态：

1. **原样保留**：交互与口径均保持一致。
2. **等价重构**：视觉或操作方式改变，但输入、结果、能力和可达性不降低。
3. **经确认移除**：属于广告、关注、登录、付费、旧解读或其他明确非目标，并记录确认依据。
4. **阻塞**：当前无法确认算法、接口或含义；保持导航关闭，不得用空壳、占位结果或猜测实现代替。

功能设计文档使用以下最小表格，按页面和操作顺序逐项填写：

| 编号 | 原始页面/入口 | 原始功能与触发条件 | 输入、输出或交互表现 | 新版承载位置 | 处理状态 | 证据与测试 |
|---|---|---|---|---|---|---|
| F01 | 表单/某模式 | 说明字段、默认值、条件显隐或操作 | 记录实际行为，不只写控件名称 | 新版模块或组件 | 原样保留/等价重构/经确认移除/阻塞 | 截图、原始响应、黄金用例或 E2E 编号 |

表格必须覆盖默认页面之外的标签页、二级页面、“更多”、宫位详情、说明页以及切换条件后才出现的功能。相同功能在多个页面出现时可以合并记录，但必须列全入口和触发条件。

不得使用“新版更简洁”“移动端放不下”作为删除功能的理由。确需精简时，优先使用分组、折叠、行内详情、弹层或局部滚动，并在对应功能设计文档中记录等价关系。

## 3. 页面骨架

### 3.1 路由和返回链路

- 首页 `/` → 专业排盘导航 `/paipan`。
- 导航 → 某一排盘表单。
- 表单 → 结果页。
- 导航返回首页，表单返回导航，结果返回表单。
- 返回按钮由 H5 自己提供，不依赖浏览器或 App 原生返回按钮。

### 3.2 页面容器

- 内容最大宽度：`480px`。
- 设计基准宽度：`390px`。
- 必须兼容：`360px`、`390px`、`430px`。
- 页面左右留白：常规 `12px`；宽度不超过370px时可降到 `10px`。
- 底部必须包含 `env(safe-area-inset-bottom)`。
- 页面使用 `overflow-x: clip`，同时要求内部组件真实不溢出，不能只靠裁切掩盖问题。

### 3.3 统一头部

- 最小高度：`62px + 顶部安全区`。
- 三列结构：`44px / 自适应标题 / 44px`。
- 返回触控区域：`44 × 44px`。
- 标题居中，25px宋体，深蓝墨色。
- 内页不放排盘记录、老师横幅或占空间的说明区。

## 4. 设计令牌

### 4.1 颜色

| 用途 | 变量 | 色值 | 使用规则 |
|---|---|---:|---|
| 宣纸上层 | `--paper-top` | `#faf6ec` | 页面渐变起点 |
| 宣纸下层 | `--paper-bottom` | `#f2ead9` | 页面渐变终点 |
| 卡片底色 | `--card` | `#fff9ed` | 实色卡片与弹窗 |
| 柔和卡片 | `--card-soft` | `rgba(255,249,237,.86)` | 普通模块 |
| 正文墨色 | `--ink` | `#2c241d` | 主要正文与数值 |
| 次级文字 | `--muted` | `#6f6257` | 标签、说明 |
| 提示文字 | `--hint` | `#9a8979` | 日期补充、次要信息 |
| 朱砂 | `--vermilion` | `#b24d34` | 主按钮、编号、选中态 |
| 深朱砂 | `--deep-red` | `#743324` | 渐变终点、重点文字 |
| 金色 | `--gold` | `#b77924` | 图标、箭头、轻提示 |
| 边框 | `--border` | `#e1d1b7` | 卡片及输入框边界 |
| 标题深墨蓝 | — | `#273746` / `#172c3f` | 页面与模块标题 |

不得在新页面中随意增加相近的米色、红色和灰色。确需新增颜色时，先补充全局变量，再更新本规范。

### 4.2 五行颜色与图标

| 五行 | 颜色 | 图标建议 |
|---|---:|---|
| 木 | `#008b62` | 树木或叶片线性图标 |
| 火 | `#c34b18` | 火焰线性图标 |
| 土 | `#8c6500` | 山形线性图标 |
| 金 | `#ad7416` | 金钱或金属线性图标 |
| 水 | `#1376a5` | 水滴线性图标 |

五行色只用于天干、地支、藏干及明确的五行数据，不作为整块背景色，避免页面过花。

### 4.3 字体与字号

- 页面标题、模块标题、重要干支：宋体序列 `Noto Serif SC / Songti SC / STSong / serif`。
- 正文、表单、数字：黑体序列 `Noto Sans SC / PingFang SC / Microsoft YaHei / system-ui`。
- 页面标题：`25px / 1.25`。
- 结果姓名或主标题：`23px`。
- 模块标题：`20px`。
- 二级标题：`18px`。
- 正文与表单输入：`16–17px`，正文行高不低于 `1.6`。
- 主要盘面干支：`21–29px`。
- 标签：`14–15px`。
- 辅助文字：常规不小于 `13px`。
- 表格中的极次要文字最低 `12px`；不得用10px以下承载需要阅读的信息。

所有数值日期使用等宽数字效果 `font-variant-numeric: tabular-nums`，减少跳动。

### 4.4 间距体系

统一使用以下间距，不新增零散数值：

| 等级 | 数值 | 典型用途 |
|---|---:|---|
| XS | `4px` | 同一数值的上下补充 |
| S | `6–8px` | 标签、胶囊、同组按钮 |
| M | `10–12px` | 字段之间、按钮之间、模块之间 |
| L | `14–16px` | 标题到正文、卡片横向内边距 |
| XL | `18px` | 卡片纵向内边距、二级模块起始 |
| XXL | `24–30px` | 空状态及独立大区块 |

强制规则：

- 页面模块之间统一 `12px`。
- 表单卡片之间统一 `12px`。
- 卡片常规内边距 `18px 16px`；结果卡横向可用 `14px`。
- 模块标题到主体内容统一 `14px`。
- 同一字段的标签与输入框间距 `7px`。
- 同组小卡片或选择按钮间距 `8px`。
- 二级标题与上一内容间距 `18px`，与下一内容间距 `10px`。

### 4.5 边框、圆角和阴影

- 所有普通边框均为 `1px`，不得叠加两层边框。
- 页面大卡片：圆角 `19px`。
- 顶部头图卡：圆角 `19–22px`。
- 输入框与滚轮触发器：圆角 `13–14px`。
- 内嵌信息表、详情气泡：圆角 `12–13px`。
- 主按钮：圆角 `16px`。
- 胶囊标签：圆角 `999px`。
- 阴影只用于抬升层级，普通卡片使用轻阴影，选中态和主按钮可稍强；禁止黑色重阴影。

表格圆角必须由一个外层容器负责：外层设置边框、圆角和 `overflow: hidden`，内部单元格只画右边和下边，最后一列与最后一行去线，避免直角露出和双线重叠。

## 5. 专业排盘导航

- 固定三列宫格，360–430px不改变列数。
- 宫格间距常规 `10px`，360px可降为 `8px`。
- 单项最小高度约 `132–139px`。
- 图标区约 `61–66px`，使用本地线性图标。
- 图标底色可暖色、冷色交替，但饱和度必须低。
- 名称16px宋体，尽量控制在四个汉字内。
- 未开放项目统一显示“即将上线”，禁用且不跳旧页面。
- 导航页只承担选择排盘，不放老师横幅、排盘记录和底部问老师入口。

## 6. 表单页规范

### 6.1 页面组成

- 顶部仅保留统一头部，不再显示“填写信息”“越准确越有价值”等大段提示。
- 每类信息放入独立表单卡片，用 `01、02、03…` 标号。
- 推荐顺序：基本身份 → 核心时间/问题 → 地区或方位 → 专项参数 → 开始排盘。
- 姓名等非必要信息明确标注“选填”。姓名为空时，结果统一显示“同修”。
- 原始页面存在多种起盘模式时，新表单必须全部提供；可重新组织为分段控件或分组卡片，但不得只实现默认模式。
- 原始字段只在特定盘式、模式或选项下出现时，必须保留同等条件显隐与校验，不得改成无效常驻字段或直接省略。

### 6.2 输入控件

- 主要输入框高度不低于 `52px`。
- 可点击选择器不低于 `56px`，复杂信息选择器建议 `64px`。
- 所有点击目标不小于 `44 × 44px`。
- 阳历、阴历、四柱等互斥模式使用统一分段控件。
- 手机端能够选择的数据，不要求用户键盘输入。
- 不在输入框下重复显示“点击滚动选择”等无必要提示。

### 6.3 移动端滚轮

- 弹窗在屏幕中间出现，不使用贴底抽屉。
- 顶部结构固定为：取消 / 居中标题 / 确定。
- 日期与时间分开点击、分开弹窗：年月日一组，时分一组。
- 阴历时柱显示时辰，例如 `12（午时）`。
- 地区始终显示省、市、区县三列；直辖市和数据缺级时也必须补齐视觉列，不允许一会一列、一会两列。
- 滚轮选中带高度 `52px`，每项高度也必须是 `52px`，依靠滚动吸附居中。
- 确认前仅修改弹窗草稿，点击确定后再写入表单。
- 弹窗需兼容安全区、键盘关闭、遮罩点击和连续快速滚动。

### 6.4 主按钮与错误

- “开始排盘”最小高度 `56px`，朱砂到深朱砂渐变，19px宋体。
- 计算中按钮禁用并显示明确状态，防止重复提交。
- 字段错误尽量靠近对应字段；服务错误使用卡片内错误条并提供重试。
- 不显示后端堆栈、接口地址或算法错误码。

## 7. 结果页规范

### 7.1 模块顺序

结果页可按业务增减模块，但建议遵循：

1. 顶部智能解读入口（仅当前明确需要智能解读的盘种；现阶段仅子平八字）。
2. 用户或问题摘要卡。
3. 基础信息。
4. 核心盘面。
5. 关系、神煞、方位或规则提示。
6. 大运、流年、流月或其他时间联动。
7. 综合参考或分值。
8. 底部智能解读入口（适用范围同上）。
9. 文化研究与娱乐参考提示。

原始结果页已有的专业模块和盘面工具必须先全部进入功能对照矩阵，再按阅读路径重新排序。默认收起不等于删除：入口必须可发现，展开后信息与原始能力等价。

### 7.2 结果卡片

- 卡片之间统一 `12px`。
- 标题使用编号章和20px宋体。
- 同级卡片使用同样的边框、圆角、背景和阴影。
- 内容少时保留正常内边距，不人为压矮；内容多时自然增高。
- 同一类字段统一使用标签在上、值在下的阅读方式。

### 7.3 信息网格

- 基础信息默认两列。
- 每格内边距 `11px 10px`。
- 标签14px、主值16px，主值可加粗到650–750。
- 日期、地区、节气等长值优先拆成两行，不把整串信息挤在一行。
- 省级与区县分行；日期与时间分行；节气日期、时刻、名称分层显示。
- 单元格底线和右线必须由位置规则统一控制，不能手工给个别格子补边框。

### 7.4 核心盘面表格

- 外层统一负责圆角与边框，禁止表格和外层同时画完整边框。
- 固定盘面优先使用 `table-layout: fixed`。
- 首列作为行标题，建议宽度 `48px`。
- 天干、地支使用宋体大字、五行色和对应图标。
- 藏干正文不小于16px，十神补充不小于12px。
- 复杂内容允许单元格内纵向排列，不允许为了保持单行而缩小字号。
- 神煞较多时纵向换行或使用标签，不截断。
- 如果五列以上仍无法清晰显示，应改为分组卡片或纵向结构；局部横滑只作为最后方案。

### 7.5 大运、流年、流月和其他序列

- 大运、流年默认两列平铺。
- 月份等短项目可三列平铺。
- 项目不足一行时保持原列宽，不把最后一项拉满整行。
- 选中项使用朱砂渐变、白字和轻阴影。
- 每个按钮至少显示主值、时间/年龄、必要补充三层信息。
- 不用横向滑动条展示十年数据；让页面纵向自然延伸。

### 7.6 选中详情气泡

- 详情必须紧跟在选中项所在行的下一行，而不是统一堆到整组选择器底部。
- 详情框上方使用14px左右的小三角，准确指向当前选中项中心。
- 选择同一行不同列时，三角位置同步移动。
- 详情框内按“标题 → 关键字段网格 → 标签”组织。
- 切换内容使用约180ms轻动画，不做大幅位移和炫技动效。
- 大运、流年、流月以及其他同类联动统一复用这一交互。

### 7.7 标签与白话解释

- 干支关系、神煞等使用可换行胶囊标签，间距6px。
- 标签仅展示名称时不强行塞解释。
- 需要白话解释时，点击标签后使用同风格的小弹层或展开区，包含：名称、通俗含义、本盘对应关系、参考边界。
- 解释文字不得写成绝对结论，避免恐吓和保证式表达。

### 7.8 专业信息分层

结果数据必须先经过专业分层，再进入组件。默认使用以下五层模型：

| 层级 | 作用 | 移动端展示方式 |
|---|---|---|
| 核心层 | 用户识别这是什么盘、当前最重要的盘面是什么 | 靠前、始终可见，字号与留白最明确 |
| 定盘与核验层 | 说明排盘条件、局式、节气、旬首、空亡等依据 | 与对应核心信息相邻；必要时默认展开 |
| 研读层 | 宫位、柱位、关系、时序等需要持续查看的专业主体 | 使用稳定盘面、分组表格或行内详情，不频繁跳窗 |
| 辅助层 | 神煞释义、方位辅助、扩展参数等特定场景信息 | 独立模块，按使用频率决定默认展开或收起 |
| 中间层 | 算法内部数组、重复字段、编码和仅供计算的数据 | 不直接展示；如确有专业价值，先转译成用户可读结果 |

分层不是固定套模板。专业主编需要根据盘种调整，但必须说明为什么某项信息靠前、为什么与另一项合并，以及为什么默认展开或收起。

### 7.9 模块、分隔与段落

- 一个一级模块只回答一个主要问题，标题应能概括这个问题，不能使用“更多信息”“相关数据”等空泛名称。
- 模块内部优先采用“模块标题 → 一句用途说明（仅在术语不直观时）→ 核心内容 → 按需详情”的结构。
- 同一判断链路使用组内分隔线或小标题，不要为每两个字段再套一张卡片；避免“卡片套卡片套卡片”。
- 一级模块依靠12px外间距、完整边框和背景区分；同组内容依靠留白、细分隔线和二级标题区分。
- 说明文字应按语义成段，移动端单段建议2–4行；超过一屏的长解释应拆成小标题或按需展开。
- 同一屏内尽量不超过三个视觉层级。若出现“页面卡片 → 内层卡片 → 小卡片 → 标签”的四层嵌套，应重新分组。
- 分隔线只表达同一模块内部的并列或阶段变化；不同专业主题应通过独立模块和留白分开。
- 展开内容必须出现在触发位置附近，再次点击可收回，并保留用户当前阅读上下文。

## 8. 文案规范

### 8.1 命名

- 页面名称与导航名称保持一致。
- 模块标题尽量为2–6个汉字，例如“基本信息”“四柱命盘”“干支留意”。
- 按钮使用动作表达，例如“开始排盘”“重新排盘”“请老师解读本盘”。
- 空姓名统一显示“同修”，不显示“未填写”“案例1”。
- 空数据统一显示“—”或“暂无相关信息”，同一模块只能选一种。

### 8.2 文字层级

- 先给用户结论或名称，再给补充信息。
- 标签用短词，长解释另起一行。
- 同一单元格不要混合超过三个信息层级。
- 数字、年份、年龄和节气之间使用清晰分隔，不堆成长句。

### 8.3 提示与声明

- 删除不帮助用户完成操作的提示词。
- 只在容易误操作或有业务风险的位置给提示。
- 结果页底部统一使用：“传统文化研究与娱乐参考，请理性看待推演结果”。

## 9. 图标规范

- 使用本地图标库中的线性或双色线性图标，保持统一笔画。
- 不使用带照片感、3D感或来源不一致的彩色素材。
- 页面功能图标使用金色、朱砂或低饱和蓝色。
- 状态图标必须配文字，不能只靠颜色表达。
- 返回、下拉、重试等系统动作在所有排盘中使用同一个图标。

## 10. 状态与反馈

每个排盘都必须设计以下状态：

- 初始状态：默认值合理，不出现空白页面。
- 加载状态：保留页面骨架，显示“正在排盘”“正在加载”等明确文字。
- 空状态：解释为什么为空，并给下一步操作。
- 校验错误：指出具体字段，不只显示“参数错误”。
- 服务错误：提供重试，保持用户已填写内容。
- 结果恢复：通过当前标签页保存的 `paipan_ref` 恢复。
- 引用过期：提示重新排盘，不展示技术错误。
- 禁用状态：降低饱和度并配文字，不能只靠透明度。

## 11. 智能老师入口与数据参数

- 当前只有子平八字结果页展示智能老师入口；其他盘种默认不展示。
- 后续某一盘种如需增加智能解读，必须先有明确的产品需求和专业内容边界，再复用统一入口样式。
- 正式接入前，按钮只展示，不提前向外部页面发送盘面。
- 正式接入时只传递一个短期参数 `paipan_ref`。
- Dify 或 MCP 通过后端读取版本化盘面，不把姓名、出生时间、地区或完整 JSON 放入 URL。
- 后续10种排盘分别使用独立 `chartType` 和版本号，但继续使用统一的 `paipan_ref` 读取方式。
- 智能解读的接口、鉴权和盘面数据契约属于功能规范；不能为了接入而改变页面视觉骨架。

## 12. 组件复用要求

后续开发应优先复用或抽离以下公共组件，禁止每个排盘复制一套样式：

- `PageHeader`：统一头部和返回链路。
- `PaipanPageShell`：宣纸背景、最大宽度、安全区。
- `PaipanSectionCard`：编号标题和卡片骨架。
- `InfoGrid` / `InfoPair`：两列信息网格。
- `ChartTable`：单边框、圆角和固定布局。
- `InlineSelectionGrid`：平铺选择和行内详情气泡。
- `MobileWheelPicker`：居中滚轮弹窗。
- `InterpretationEntry`：顶部和底部智能解读入口。
- `PaipanEmptyState`：加载、过期、错误和重试状态。
- `FiveElementLabel`：五行颜色与图标。

公共视觉令牌放在全局样式中；单个排盘只能增加与其数据结构有关的局部样式，不得覆盖全局字号、卡片圆角和模块间距。

## 13. 允许变化与禁止变化

### 13.1 允许按盘变化

- 输入字段的视觉分组和呈现顺序；算法语义、选项集合、默认行为和条件规则必须与已确认口径一致。
- 核心盘面内部的数据结构。
- 结果模块数量和专业术语。
- 两列、三列、表格或纵向卡片的内容布局。
- 是否存在时间序列、方位图、数字矩阵等专项组件。

### 13.2 不允许自行变化

- 页面背景、基础颜色和字体体系。
- 页面最大宽度和安全区。
- 头部高度、返回按钮和标题位置。
- 卡片外观、模块间距和标题样式。
- 表单控件高度、主按钮和错误样式。
- 适用盘种的智能解读入口、文化提示和状态页口径。
- 移动端字号下限和无整页横向溢出要求。

## 14. 新排盘开发流程

每增加一种排盘，按以下顺序执行：

1. 固化原始页面地址、版本化脚本地址、采集时间与 SHA-256，并保存表单、结果和必要子页面截图。
2. 实际操作全部起盘方式和结果工具，形成原始功能清单与“原始功能对照矩阵”；不能只根据路由名、接口名或单个样例推断。
3. 为每种起盘模式准备至少一个脱敏请求、原始响应和可信黄金结果；条件组合较多时增加边界样例。
4. 由国学术数专业主编列出输入条件、起盘依据、核心盘体、研读关系、辅助信息和算法中间信息。
5. 写出专业阅读路径，并为每组信息标注“始终可见、默认展开、按需展开、不直接展示”。
6. 说明模块的合并与拆分理由，并逐项说明原始功能是原样保留、等价重构、经确认移除还是阻塞。
7. 标出哪些模块直接复用公共组件，哪些确实需要新组件。
8. 先用文字线框确认模块顺序、分隔方式和展开位置，再完成390px视觉设计。
9. 验证360px和430px，先保证字号和可读性，再调整信息密度。
10. 对所有表格检查四角、双线、最后一行和最后一列。
11. 对所有模块检查专业标题、外间距12px、标题间距14px和卡片内边距。
12. 对所有选择器检查平铺、选中态、行内展开和气泡三角位置。
13. 对加载、空态、错误、刷新恢复、返回链路及全部原始结果工具做完整测试。
14. 逐项执行功能对照矩阵，确认没有“未实现但未记录”的功能，再生成三种宽度预览图。
15. 由功能完整性、专业逻辑与移动端视觉三方面共同确认后，才能开放导航并进入下一种排盘。

## 15. 验收清单

### 15.0 原始功能完整性

- [ ] 已记录原始页面、全部子页面、脚本版本、采集时间和 SHA-256。
- [ ] 已实际操作并记录全部起盘方式，不只验证默认模式。
- [ ] 全部字段、选项、默认值、条件显隐、互斥关系和校验规则均有新旧对应。
- [ ] 全部结果模块、详情层级、标记说明和辅助信息均有新旧对应。
- [ ] 上一/下一、切换、联动、展开、放大、重排等原始结果工具均已覆盖。
- [ ] 每项原始功能均标记为原样保留、等价重构、经确认移除或阻塞，不存在空白项。
- [ ] “经确认移除”均有非目标说明和确认依据；没有因开发成本或页面空间静默删减。
- [ ] 每种起盘模式及关键条件组合都有黄金结果，差异文件能够解释所有字段差异。
- [ ] 参考站当前行为与传统算法预期不一致时，以已确认验收口径为准并显式记录，不私自修正。

### 15.1 视觉

- [ ] 页面顺序符合该盘种的专业阅读路径，不是接口字段罗列。
- [ ] 每个模块回答一个明确问题，合并与拆分有专业理由。
- [ ] 核心、核验、研读、辅助和中间信息的展示层级合理。
- [ ] 展开与收起策略符合使用频率和阅读上下文。
- [ ] 所有同级模块之间均为12px节奏。
- [ ] 卡片圆角、边框粗细和阴影一致。
- [ ] 表格四角无直角露出，无双线或重叠边框。
- [ ] 文字层级清楚，重要值加粗，长信息合理换行。
- [ ] 正文不小于16px，辅助说明不小于13px。
- [ ] 五行颜色和图标使用一致。
- [ ] 无连续字段堆叠、无无意义卡片嵌套，段落与分隔形成清楚节奏。

### 15.2 交互

- [ ] 所有触控目标至少44px。
- [ ] 日期与时间分开选择。
- [ ] 地区滚轮始终三列。
- [ ] 滚轮选中项精准居中，无滚动跑偏。
- [ ] 大量选项优先平铺，不要求横向滑动。
- [ ] 详情气泡紧跟选中行，三角准确指向选中项。
- [ ] 返回链路符合“结果 → 表单 → 导航 → 首页”。

### 15.3 响应式和技术

- [ ] 360×780、390×844、430×932均无整页横向溢出。
- [ ] 安全区、长姓名、长地区和大字号场景正常。
- [ ] 页面刷新可通过 `paipan_ref` 恢复，过期后有明确提示。
- [ ] 加载、空态、错误和重试均可见、可操作。
- [ ] Typecheck、单元测试、构建和Playwright移动端E2E全部通过。

## 16. 例外管理

如果某种盘面因专业结构确实无法遵守某条布局规则，必须在开发前说明：

- 为什么现有组件无法承载。
- 尝试过哪些两列、三列、分组或纵向方案。
- 例外是否只影响局部组件。
- 360、390、430px下如何保持可读。
- 是否影响原始功能完整性；如果影响，必须先取得明确确认，不能把布局例外自动视为功能删减许可。

例外只能局部生效，不能通过覆盖全局变量改变其他10种排盘。
