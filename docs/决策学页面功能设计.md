状态：待教师验收<br>

页面路由：`/paipan/juece`

## 1. 开放门槛

功能代码和测试可以在本地完成，但生产路由与排盘导航入口必须保持禁用。本地验收使用 `VITE_ENABLE_JUECE_VALIDATION=true` 注册直达路由；普通生产构建默认不注册。只有六类黄金盘全部经教师确认、自动回归全部通过后，才可在单独提交中移除路由开关，并为 `catalog.ts` 增加路径、设置 `enabled: true`。

当前 `catalog.ts` 中“决策学”仍为 `enabled: false`，普通构建也不会注册 `/paipan/juece`，因此状态只能是“待验收”，不能表述为已上线或已开放。

## 2. 范围与非目标

本期只实现时家决策的结构化起盘、短期恢复、前后时辰换盘与盘面展示。

明确不包含：

- 旧外站“天阳决策”。
- 旧版个案吉凶断语或算法调试日志。
- 智能老师入口、Dify 调用或问答上下文。
- 浏览器端或 Fastify 端排盘算法。
- 对九宫、八字表格等盘种特有结构的公共抽象。

## 3. 系统边界

| 层级 | 职责 |
|---|---|
| React H5 | 收集互斥条件、展示结构、保存当前标签页引用、触发换盘 |
| Fastify | Zod 校验、Java 调用、错误映射、创建及恢复短期上下文 |
| Java `ShijiaJueceEngine` | 历法、真太阳时、定局、转盘/飞盘和九宫计算 |
| SQLite | 保存引用哈希、盘型、版本、请求和结果；不保存明文引用 |

公开接口：

- `POST /api/v1/paipan/juece/chart`
- `POST /api/v1/paipan/juece/context`

Java 内部接口：

- `POST /internal/v1/juece/chart`

上下文固定标识：

- `chartType: "shijia_juece"`
- `schemaVersion: "guoxue.paipan.shijia_juece.v1"`

## 4. 输入规则

表单按以下三段组织，结构化请求使用互斥联合类型，不依赖“无关字段留空”的弱约定。

### 4.1 起盘条件

- 日期来源：阳历或阴历。阴历先经现有历法接口解析为阳历时间。
- 标准时间：请求中只允许 `{ mode: "standard" }`。
- 真太阳时：必须使用 `{ mode: "true_solar", areaCode: "六位地区码" }`。
- 地区加载失败时提供重试，且真太阳时不能提交。

### 4.2 盘式与定局

- 转盘必须指定寄宫：寄坤宫、阳艮阴坤、寄四维、随节令。
- 飞盘必须指定顺逆：阳顺阴逆、阴阳皆顺；不接受寄宫字段。
- 自动定局：拆补、置闰、茅山。
- 手工定局：必须同时指定阴/阳遁和 1–9 局。

### 4.3 标记与寄宫

- 旬空标记：时空、日空、月空、年空。
- 寄宫只在转盘出现；切换飞盘后不提交寄宫字段。

## 5. 输出与阅读顺序

结果严格按“起局与核验 → 九宫主盘 → 选中宫位行内详情 → 标记说明 → 文化提示”阅读。

起局与核验包含：原始钟表时间、起局使用时间、真太阳时及地区、阴历、四柱、四柱空亡、前后节气、阴阳遁局数、旬首、值符、值使和马星。

九宫公共字段包含宫序、卦名、方位、五行、天地盘、空亡、马星、值符和值使。转盘增加中宫寄宫结构；飞盘增加暗干支和天地八神。公开响应不包含旧包类名、样式字段、过程对象或控制台日志。

宫位详情只解释当前宫位的神、星、门、天地盘、寄宫、暗干支和结构标记，不输出个案吉凶判断。

## 6. 状态与交互

- 提交中：同一表单实例使用同步锁和禁用态阻止重复提交。
- 换盘中：上一/下一时辰按钮禁用，按原始钟表时间移动两小时。
- 换盘失败：保留当前盘、原引用和时间，显示原方向的重试按钮。
- 恢复中：读取当前标签页 `sessionStorage` 中的 `paipan_ref`。
- 引用失效：清理本地引用，展示重新排盘入口。
- 页面刷新：只用引用调用 context 接口，不把请求参数写入 URL。
- 动效：沿用全站 `prefers-reduced-motion` 降级规则。

三档验收尺寸为 360×780、390×844、430×932；九宫固定三列，不允许整页横向溢出，交互目标不少于 44px。

## 8. 黄金盘与已知差异

六类材料位于 `docs/juece-golden/case-01` 至 `case-06`，每例均包含请求、旧算法原始结果、新版标准化结果、字段差异和 390px 结果图。

盘面映射字段（四柱、空亡、阴阳遁局、旬首、值符值使、马星及九宫结构）六例均一致。待教师确认的已知差异为：

- 六例前后节气名称一致，秒值因旧内嵌历法表与当前 Java 历法源不同，相差 5–9 秒。
- case-02 真太阳时旧包为 `10:02`，当前复用的 Java 地区/真太阳时能力为 `10:01`；四柱和盘面不受影响。

这些差异不得由开发侧擅自判为“可接受”，需教师在黄金盘确认表中逐例签认。
