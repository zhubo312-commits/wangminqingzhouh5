## 1. 开放门槛

业务方确认“只要结果和参考网址一样就算通过”。六类黄金盘已按参考站当前接口和版本化生产脚本重建，六例全部为 `all_mapped_fields_equal`、映射字段差异 0，因此不再设置教师主观确认门槛。

普通构建现已注册 `/paipan/juece` 与结果路由，`catalog.ts` 中“决策学”为 `enabled: true`。本次只做本地开发、验收和提交，不推送、不部署。

## 2. 范围与非目标

本期实现时家决策的结构化起盘、短期恢复、前后时辰换盘与盘面展示。

明确不包含：

- 旧外站“天阳决策”。
- 个案吉凶断语或算法调试日志。
- 智能老师入口、Dify 调用或问答上下文。
- 浏览器端或 Fastify 端排盘算法。
- 对九宫、八字表格等盘种特有结构的公共抽象。

## 3. 系统边界

| 层级 | 职责 |
|---|---|
| React H5 | 收集互斥条件、展示结构、保存当前标签页引用、触发换盘 |
| Fastify | Zod 校验、Java 调用、错误映射、创建及恢复短期上下文 |
| Java `ShijiaJueceEngine` | 真太阳时、飞盘公式、参考站转盘同源星河引擎和标准化九宫结果 |
| SQLite | 保存引用哈希、盘型、版本、请求和结果；不保存明文引用 |

公开接口：

- `POST /api/v1/paipan/juece/chart`
- `POST /api/v1/paipan/juece/context`

Java 内部接口：`POST /internal/v1/juece/chart`。

上下文固定为：

- `chartType: "shijia_juece"`
- `schemaVersion: "guoxue.paipan.shijia_juece.v1"`

## 4. 输入规则与参考站兼容

### 4.1 起盘条件

- 日期来源为阳历或阴历；阴历先经现有历法接口解析为阳历。
- 标准时间只提交 `{ mode: "standard" }`。
- 真太阳时提交 `{ mode: "true_solar", areaCode: "六位地区码" }`。
- 地区加载失败时可重试，真太阳时在地区不可用时不能提交。

### 4.2 转盘

参考站生产代码确认：转盘结果页固定调用 `app/qimen/getXingHeQimenH5`，只传 `birthDay`、`question`、`isKe=4`；历史表单中的定局、旬空、寄宫和真太阳时地理参数不会改变转盘盘面。

新版因此直接展示固定口径：

- 拆补定局。
- 时空标记。
- 中宫寄坤。
- 使用原始钟表时间起局；若选择真太阳时，仍返回校正结果供核验，但不以校正时间改变转盘。

接口继续接受旧的结构化转盘请求，以兼容已保存上下文，但响应统一按上述参考站口径计算。

### 4.3 飞盘

- 顺逆规则：阳顺阴逆、阴阳皆顺。
- 定局：拆补、置闰、茅山，或手工指定阴/阳遁与 1–9 局。
- 旬空：时空、日空、月空、年空。
- 飞盘不接受寄宫参数；真太阳时会参与飞盘起局。

## 5. 输出与阅读顺序

结果按“起局与核验 → 九宫主盘 → 选中宫位行内详情 → 标记说明 → 文化提示”阅读。

起局与核验包含原始钟表时间、起局使用时间、真太阳时及地区、阴历、四柱、四柱空亡、前后节气、阴阳遁局数、旬首、值符、值使和马星。

九宫公共字段包含宫序、卦名、方位、五行、天地盘、空亡、马星、值符和值使。转盘保留参考站的中宫寄宫合干与隐干；飞盘显示暗干支和天地八神。公开响应不包含旧包类名、样式字段、过程对象或控制台日志。

宫位详情只说明当前宫位的神、星、门、天地盘、寄宫、暗干或暗干支和结构标记，不输出个案吉凶判断。

## 6. 状态与交互

- 同一表单实例用同步锁和禁用态阻止重复提交。
- 上一/下一时辰按原始钟表时间移动两小时并创建新引用。
- 换盘失败时保留当前盘、原引用和时间，并提供原方向重试。
- 当前标签页仅在 `sessionStorage` 保存 `paipan_ref`；刷新通过 context 接口恢复。
- 引用过期或不匹配时清理本地引用并提供重新排盘。
- 沿用全站 `prefers-reduced-motion` 降级规则。

三档验收尺寸为 360×780、390×844、430×932；九宫固定三列，不允许整页横向溢出，交互目标不少于 44px。

## 7. 参考来源与可复现证据

`docs/juece-golden/source-manifest.json` 固化：

- 参考站入口、采集时间。
- 当前 app、表单、转盘、飞盘四个版本化生产脚本 URL 与 SHA-256。
- 旧包四个关键迁移文件及 SHA-256。

转盘使用参考站当前星河接口的原始响应；飞盘使用参考站当前生产脚本对应的冻结算法结果。Java 运行时不访问外网：转盘复用同源本地星河引擎，飞盘使用本地无状态公式，并固化参考站 1899–2101 年节气秒值表以消除边界差异。

## 8. 黄金盘结论

六类材料位于 `docs/juece-golden/case-01` 至 `case-06`。每例包含请求、参考站原始结果、旧包迁移结果、新版标准化结果、字段差异和 390px 结果图。

截至 2026-08-11，六例的四柱、四柱空亡、所选旬空、节气时间、阴阳遁局、旬首、值符、值使、马星及九宫结构映射字段均一致；六个 `field-diff.json` 的差异数均为 0，验收通过。
