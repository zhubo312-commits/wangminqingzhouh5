# 姓名学与康熙笔画采用规则

## 结论

姓名学运行不使用现代总笔画。用户输入先通过已审计的简繁/异体关系规范到康熙繁体，再使用已授权 `kangxizidian.cn` 详情页的严格康熙笔画计算：

- `chinese_dictionary.bihua` ← 规范繁体的 `strict_kangxi_strokes`，作为运行计算值。
- `chinese_dictionary.kx_bihua` ← 同一严格康熙笔画，保留明确来源与兼容字段。

同一字形两个网站笔画字段都存在时必须一致；不一致属于阻塞发布的来源冲突。简繁字仍保留两个母库来源记录，但姓名学输入“阳”会规范为“陽”并按 17 画计算；这一转换会在结果页明示。

## Unihan 的边界

- `kTotalStrokes`、`kAlternateTotalStrokes` 是现代字形笔画，只进入参考观察层，不参与姓名学计算和投影验收。
- `kKangXi`、`kIRGKangXi` 是康熙字典页码/位置索引，不是笔画数，只用于定位扫描页和人工核验。
- `kMandarin` 可在网站缺拼音时补主拼音；简繁异体字段可补关系表。
- Unihan 不补姓名学笔画、严格康熙笔画或姓名学五行。

## 自动门槛

- 每个非空姓名学/康熙笔画必须存在同值的 `canonical_decisions` 记录。
- 网站姓名学笔画与同字形网站康熙笔画不一致时生成 error。
- 网站与 Unihan 现代笔画差异只生成 info 汇总，不阻塞姓名学发布。
- 缺失值保持 `NULL + absence_reason`，不得用现代笔画推算。
- `project-chinese` 只接受已发布母库，并再次核对上述决策记录。
