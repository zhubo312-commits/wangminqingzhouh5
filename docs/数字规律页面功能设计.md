## 1. 结论与阻塞

参考站表单、结果页脚本、接口位置和一份脱敏结果已经冻结，但核心算法位于未取得源码或规则说明的服务端 `app/shenshu/getShenshu`。现有证据只能证明已保存样本，不能证明全部公开输入域的先天数、后天数、阴阳、特殊数组与位置化解读规则。

因此本稿只记录产品功能与候选契约，不授权实现本地 Engine；`catalog.ts` 必须继续保持 `enabled: false`。不得通过有限接口探针反推完整规则，不得在运行时依赖参考站。

解除阻塞至少需要以下一种可审计来源，并由业务方确认版本：

1. 参考站服务端算法源码及完整数组/解读规则表；或
2. 由算法负责人签字确认的规则规格，覆盖全部输入边界、十二数映射、日期换日、特殊数组、位置差异和文案；或
3. 业务方明确授权且足以覆盖全域的黄金语料与差异验收方案。

## 2. 已确认的输入与页面行为

- 姓名必填，原页面输入框 `maxlength=10`。
- 性别默认男，可选男/女；原页面向接口传“男”或“女”。
- 生时由参考页公共农历选择器收集，提交时转换为阳历年、月、日、时、分。
- 原页面校验姓名非空和日期数组完整，关注状态会阻止输入/提交。
- 结果页请求 `GET app/shenshu/getShenshu`，请求字段为 `userName`、`birthDay`、`sex`。
- 结果先显示个人信息，再显示先天数/阴阳/五行、后天数/阴阳/五行、特殊数组解读；无解读时显示“无内容解读”。
- 关注校验、广告、活动弹窗、悬浮营销、企业微信、登录与付费均不属于新页面目标。

尚未确认：参考日期允许范围、23:00 换日口径、姓名或性别是否参与任意算法分支、非法/极值输入的服务端行为。

## 3. 专业阅读路径（候选）

`个人与生时核验 → 先天数 → 后天数 → 特殊数组与位置化解读 → 参考边界`

先天数与后天数拟保留年、月、日、时四列，数字、阴阳和五行保持同列。特殊数组拟按数字组合、出现位置、数组类别、结果解读展示；未命中时显示明确空态。该结构只用于后续设计验收，不代表算法已可开发。
