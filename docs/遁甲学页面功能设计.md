# 遁甲学页面功能设计

版本：1.0  
日期：2026-08-11  
适用路由：`/paipan/dunjia`、`/paipan/dunjia/result`

## 1. 定位与旧版依据

“遁甲学”对应旧 `yipu-h5` 的 `purityQimen` 页面。旧版当前实际启用的业务口径为：

- 盘式：转盘。
- 局式：拆补。
- 寄宫：寄坤二宫。
- 旬空：时空。
- 起盘参数：日期与时间。
- 旧版计算入口：`getXingHeQimenH5`，`isKe=4`。
- 新版计算实现：本地 Java 服务复用 `sunland/oversea@d0f9b7f` 的奇门算法，Fastify 只负责校验、转换和短期上下文存储，不再调用旧系统线上接口。

飞盘、置闰、茅山、手工选局在旧页面中均未开放，本期不制造不可用选项。

## 2. 页面结构

### 2.1 表单页

1. 吸顶统一头部，标题“遁甲学”。
2. “起盘时间”卡片：阳历、阴历分段选择；日期与时间分别使用居中滚轮。
3. “起盘方式”卡片：展示“转盘、拆补、寄坤二宫、时空”，作为当前算法口径说明，不伪装成可切换选项。
4. 主按钮“开始排盘”。
5. 服务错误在卡片内展示，保留已选择时间并允许重试。

### 2.2 结果页

1. 起局信息：将局式、阴阳遁局数、阳历、阴历、四柱、空亡、节气、旬首、值符、值使和马星合为一张卡片；节气与旬首始终展开，因为它们是定局与校验盘面的依据。
2. 九宫盘：固定三乘三布局，顺序为 `4、9、2 / 3、5、7 / 8、1、6`；每宫展示宫位、八卦、方位、八神、九星、八门、天盘干、地盘干、旬空与四害标记。
3. 点击宫位后，详情紧随该宫所在行向下展开；再次点击当前宫位收起。中宫没有八神、九星和八门，不提供无意义的展开操作。
4. 宫位详情使用清楚的类别说明：八神为辅助象意，九星为天时象意，八门为行动与人事象意，并展示隐干、天地盘、四害和十二长生。
5. 天门地户：作为默认收起的“出行辅助”模块，仅展示天三门（太冲、小吉、从魁）与地四户（除、危、定、开）所在方位，不把十二地支计算中间表直接展示给用户。
6. 颜色说明与文化提示。
7. 遁甲学不展示老师解读入口；当前只有子平八字需要智能老师解读。

## 3. 视觉与交互

- 完整遵循《专业排盘统一设计规范》。
- 设计基准为390px，同时验收360px与430px。
- 页面不得整页横向滚动；九宫盘必须在360px宽度内完整显示。
- 九宫盘以边框、字号、留白建立层级，不使用高饱和大色块。
- 入墓、击刑、门迫、刑墓、旬空分别使用文字与轻量颜色/符号双重表达，不能只靠颜色。
- 点击目标至少44px；动态详情使用 `aria-expanded` 与可见焦点。
- 只使用150–200ms的透明度或位移动效，并尊重 `prefers-reduced-motion`。

## 4. 数据契约

- `chartType`: `dunjia`
- `schemaVersion`: `guoxue.paipan.dunjia.v1`
- 输入：标准化阳历时间 `chartDateTime`。
- 输出：`overview`、`palaces`、`heavenEarthGates`。
- 服务端保存版本化盘面快照并返回短期 `paipan_ref`。
- 前端结果刷新时仅凭 `paipan_ref` 恢复；URL不包含时间或完整盘面。
- 遁甲结果页不接入智能老师；`paipan_ref` 当前仅用于页面刷新恢复和受控服务端上下文读取。

## 5. 状态与验收

- 初始、排盘中、服务错误、结果恢复、引用过期均有明确页面状态。
- 本地算法服务超时或响应异常时显示可重试提示；字段不完整时不渲染半张盘。
- 合同测试固定一份脱敏样例响应，覆盖九宫排序、空亡、四害和中宫空字段。
- 完成类型检查、单元测试、构建与360/390/430px Playwright验收后，才视为可交付。
